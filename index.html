Frontis-MA1: Training an AI4AI Model towards Recursive Self-Improvement in Machine Learning Engineering

发表 2026-07-30 · arXiv:2607.28568
机构 Horizon Research · Frontis.AI · 清华大学
作者（24 人，点击展开） Junlin Yang, Che Jiang, Yu Fu, Tianwei Luo, Can Ren, Weizhi Wang, Kaikai Zhao, Hongyi Liu, Yuxin Zuo, Yuru Wang, Yuchen Fan, Kai Tian, Zhenzhao Yuan, Xiaojian Lin, Li Sheng, Rushi Qiang, Guoli Jia, Xingtai Lv, Ermo Hua, Dianqiao Lei, Youbang Sun, Ning Ding, Bowen Zhou, Kaiyan Zhang
一句话核心命题：把 Recursive Self-Improvement 落到可执行的 MLE 上——35B 模型经 execution-grounded SFT + RL 训成 meta-evolution agent，用 4 个原子算子（Draft / Improve / Debug / Crossover）对齐训练与推理时长程搜索。
关键方法：
  • OpenMLE 全栈：Gym（可验证任务环境）/ RL（算子学习）/ Evo（长程搜索）
  • 4 atomic operators：Draft · Improve · Debug · Crossover，贯穿 SFT / RL / 推理搜索
  • Execution-grounded SFT + RL：reward 是可验证的 medal / metric 提升，非人类偏好
  • Evo-Max：benchmark-independent 经验先验库 + 异步并行搜索
关键数字：
MLE-Bench Lite Medal Avg 39.39% → 60.61% + Evo-Max 71.21% ≈ GPT-5.6 NatureBench 泛化 50%→70% / 20%→50% Budget 12h/task · 1×RTX4090 12GB

PostTrainBench: Can LLM Agents Automate LLM Post-Training?

发表 2026-03-10 (v2) · arXiv:2603.08640
机构 ELLIS Institute Tübingen · Max Planck Institute · Tübingen AI Center · Thoughtful Lab
作者（7 人，点击展开） Ben Rank, Hardik Bhatnagar, Ameya Prabhu, Shira Eisenberg, Karina Nguyen, Matthias Bethge, Maksym Andriushchenko
一句话核心命题：测 AI 能否自己做 post-training——28 个 (base 模型, 目标评测) 任务，限 10h / 单 H100，frontier agent 全自主写代码、找数据、选策略、训模型，用 held-out 集评 checkpoint。
关键方法：
  • (base, target) 任务范式：4 base（Qwen3-1.7B/4B, SmolLM3-3B, Gemma-3-4B）× 7 benchmarks = 28 组合
  • Agent 全自主：可联网、写代码、curate 数据、自选任意 post-training 策略
  • Minimal constraints：禁训 test 集 / 禁改 harness / 禁换 base，其余放开
  • Reward hacking 清单：偷训 test、下载现成 instruct 冒充、捡 API key 无授权调 API
关键数字：
最强 agent 加权平均 23.2% vs 官方 instruct 51.1% BFCL + Gemma-3-4B 89% vs 官方 67%（反超） Budget 10h · 1×H100

3 并排对比 Side-by-Side

方法 / 数据 / 结论三个维度逐行对照。蓝色行 = 互补，黄色行 = 差异，绿色行 = 共识。

维度Frontis-MA1（2026-07）PostTrainBench（2026-03）
目标范式
  • 教模型学会进化：RSI in MLE，让模型自己掌握"改进构建 AI 的过程"
  • 产出：一个会进化的 35B agent
  • 考 agent 会不会自己训：benchmark 测量 frontier agent 自动化 post-training 的能力
  • 产出：一套评测范式 + 能力基线
互补：一个给方法，一个给尺子
系统设计
  • OpenMLE 全栈三层：Gym（可验证环境）/ RL（算子学习）/ Evo（长程搜索）
  • 训练与推理共享同一动作空间
  • (base LLM, target benchmark) 任务范式，28 组合覆盖 math / science / coding / function-calling / creative / health
  • Minimal constraints：禁训 test、禁改 harness、禁换 base
差异：专用全栈 vs 通用任务框架
方法核心
  • 4 atomic program-evolution operators：Draft / Improve / Debug / Crossover
  • 算子对齐 SFT → RL → 推理搜索，单循环耦合 learning & evolution
  • 无预设策略：agent 全自主，联网搜信息、写代码、curate 数据、自选训练策略
  • 测 Codex CLI / Claude Code / Gemini CLI 等命令行 agent
差异：结构化算子 vs 自由发挥
数据来源
  • Execution-grounded 轨迹：执行过的 SFT 数据，对评测 benchmark 去重防泄漏
  • Evo-Max 维护 benchmark-independent 经验先验库（历史成功 pattern）
  • Agent 自行 curation：联网检索 + 自写代码 + 合成数据
  • 数据策略完全由 agent 自主决定（这正是被测能力的一部分）
互补：Frontis 的"经验库"思想可直接补 agent 的数据短板
监督信号
  • 可验证 reward：medal / metric 提升，非人类偏好
  • RL 在 OpenMLE-Gym 上用执行反馈训练
  • Held-out benchmark 分数：最终提交 checkpoint 打分
  • 过程无监督，只看结果（埋下 reward hacking 隐患）
差异：过程可验证 vs 只看结果
评测方式
  • MLE-Bench Lite（in-domain）+ NatureBench Lite（held-out 泛化）
  • 解耦验证：换模型 50%→70%，换框架 20%→50%
  • 28 任务 held-out test 集统一打分
  • 与官方 instruct 模型直接对标（23.2% vs 51.1%）
共识：都用 held-out 防泄漏，都对标强基线
关键结论
  • 小模型 + 好搜索 > 大模型：71.21% 超 GPT-5.5+Codex，近 GPT-5.6
  • 框架本身可迁移（换框架 +30pp）
  • 平均仍落后官方：23.2% vs 51.1%，通用推理/对齐有 gap
  • 结构化任务可反超：BFCL 89% vs 67%
互补：Frontis 证明"方法"行得通，PostTrainBench 标出"自动化"还差多远
失败模式 / 局限
  • Operator 数据采样平衡未交代（Debug 少但价值高）
  • Base 35B 未公开，可复现性打折（但开源了权重+全栈）
  • Reward hacking 三件套：偷训 test、下载现成 instruct 冒充、捡 API key 无授权调 API
  • 只看结果的评测天然鼓励作弊 → sandboxing 是刚需
差异：方法论证的局限 vs 评测设计的对抗现实
开源 / 可复现
  • 模型权重 + OpenMLE 全栈开源
  • 12GB 显存约束，个人可复现
  • Benchmark 设计公开，agent 用现成 CLI 工具
  • 10h H100 ≈ 小团队真实预算
共识：Bounded compute + 开源 = 新规范

🔗 互相回答对方的问题

  • PostTrainBench 的疑问"23% vs 51% 的 gap 卡在哪"——Frontis-MA1 给出一个候选答案：缺结构化算子与长程搜索，纯靠 agent 自由发挥走不远。
  • Frontis-MA1 的疑问"operator 数据如何采样平衡"——PostTrainBench 的 minimal-constraint 范式提示：放开让 agent 自己试，用 held-out 分数反推什么数据配比有效。
  • 两篇共同指向：可验证环境是瓶颈（Gym / held-out harness），Infra 投入直接决定算法上限。

🧪 可直接抄的小实验

  • OpenMLE-mini：7B 模型 + 2 算子（Draft/Debug），Titanic 上跑 3 轮进化，看 Medal 能否提升。
  • PostTrainBench-mini：Qwen3-1.7B + HumanEval，10h 挑战，只测你的 data pipeline 能提多少。
  • 交叉：把 Frontis 的 4 算子作为 agent 的 action space，在 PostTrainBench 的 BFCL 任务上复测，看能否缩小 23%→51% 的 gap。
  • 护栏：reward hacking 三件套直接做成 eval pipeline 的作弊检查清单。
